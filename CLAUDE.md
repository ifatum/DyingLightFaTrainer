# FaTrainer | Dying Light

In-game trainer for Dying Light 1 on Linux (Steam + Proton). It is a Windows DLL loaded by the game as a proxy `xinput1_3.dll` and draws an ImGui menu over the game (Insert or F8).

## Rules

- Never write comments in any file of this project: no `//`, `/* */`, `#` comments, docstrings or HTML comments. Code must explain itself through names.
- The product name is exactly `FaTrainer | Dying Light`. All UI text is English.
- After every finished change: build, run the self test, render the preview when the UI changed, then commit and push to `origin main` without asking. Use clear commit messages.
- Never include any hint that the code had AI assistance: no `Co-Authored-By` trailers, no "Generated with" lines, no mentions of Claude or AI in commits, pull requests, code or docs. Commit as the configured git user only.
- Use the available skills and plugins for every task where one applies (brainstorming, planning, debugging, verification, code review, simplification).
- Keep game-derived data out of git: `src/items.h` and `src/font.h` are generated by `gen_data.py` and ignored.
- Never call game functions from the render thread. Queue them with `on_game_thread`, which runs them on the window thread.
- Memory access goes through `game::rd`, `game::rdv` and `game::wr`. Never use `ReadProcessMemory` on Wine: every call is a wineserver round trip and stalls the game.
- ImGui asserts are routed to the log by `src/imconfig_dlt.h`. Check the log for `imgui assert` after UI changes.

## Layout

- `src/dllmain.cpp`: xinput proxy exports, D3D11 Present hook, input handling, menu UI, game-thread queue, logging.
- `src/game.h`: RTTI vtable lookup, heap scan, inventories, item names, stat calibration, giving items.
- `src/xinput1_3.def`: export ordinals 2 to 8 matching the real `xinput1_3.dll`.
- `src/imconfig_dlt.h`: ImGui user config.
- `gen_data.py`: reads the game paks and writes `src/items.h` (item ids, English names, script stats) and `src/font.h`.
- `test/fake.h`: fake game world with the real memory layout.
- `test/selftest.cpp`: RTTI lookup against the real `gamedll_x64_rwdi.dll` plus logic tests on the fake world.
- `test/preview.cpp`: D3D11 window that loads the trainer for screenshots.
- `third_party/imgui`: Dear ImGui 1.91.9 and Roboto.

## Game internals (gamedll_x64_rwdi.dll)

Classes are found by RTTI name at runtime, so vtable addresses survive game updates. Offsets were read from the disassembly.

- `InventoryMoney`: money is `int` at `+0x40`. Virtual 20 is AddMoney(amount, reason), 21 is RemoveMoney.
- Item inventories share one layout: `+0x08` type, `+0x40` item pointer array, `+0x48` count, `+0x58` capacity.
- Inventory factory types: 1 `InventoryAmmo`, 2 `InventoryCollectable`, 3 `InventoryLooseItems` (materials and consumables), 4 `InventoryMain`, 5 and 6 `InventorySpecial`, 7 `InventoryNet`.
- `InventoryMain` with capacity `-1` is the stash, with a positive capacity it is the backpack.
- `InventoryMain` virtual 6 is AddItem(ItemData*, int reason, bool flag). It copies the ItemData, merges stacks, otherwise allocates a new item.
- Item object: ItemData (0xC0 bytes) starts at `+0x40`. ItemData `+0x00` count, `+0x18` ItemDescWithContext, `+0x20` ItemDesc pointer, `+0x60` ItemDescWeaponModification pointer or null.
- ItemDesc: name `char*` at `+0x18`.
- `ItemManager`: all ItemDescs at `+0x50` with count at `+0x58`. Virtual 4 finds a desc by name.
- ItemDesc stat offsets are not hardcoded. `calibrate_stats` matches every desc against the script values in `items.h` and only enables a stat when most samples agree.
- Rarity is the script `Color` enum: 0 White, 1 Green, 2 Blue, 3 Violet, 4 Orange, 5 Platinum.

## Reverse engineering

Python with capstone through nix works well for the disassembly:

```
nix-shell -p python3Packages.capstone
```

Find vtables through RTTI: type descriptor name `.?AV<Class>@@`, complete object locator with signature 1 and offset 0, vtable follows the pointer to the locator.
